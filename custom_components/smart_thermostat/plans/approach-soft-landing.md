# Ранняя посадка TRV при горячей батарее

## Факт (спальня 04.11.2026)

Цель 23 весь день (constant-23). После утреннего догона offset ≈ +2.8…+4.7.
В ~15:47 room пересёк 23, TRV ещё **26**, local ~24+. Soft-landing PID
уже гасил коррекцию, но **offset** держал уставку высокой → инерция до
пика **24.3** (~20:19). `overshoot_close` сработал уже после перелёта.

## Причина

`t_trv ≈ t_effective + offset + soft_pid`. Мягкая посадка трогает только
PID. При большом положительном offset у цели TRV остаётся ≫ room, клапан
продолжает «видеть» тепло, комната перелетает.

## Фикс

`helpers.approach_trv_ceiling`:

- `error > 0` и `error ≤ deadband + soft_landing_span`;
- батарея горячая: `local ≥ room + HEAT_FLOW` **или** `local ≥ t_target`
  (иначе порог room+1.5 срабатывает слишком поздно);
- потолок = `room + UNDERHEAT_TRV_MARGIN` (= underheat floor).

Срезаем лишний offset/PID, инвариант недогрева не ломаем. В active и
deadband hold; `last_action=approach_close`; cooldown не ждём (как
overshoot). Одновременно `approach_trim`: offset шагает к
`room+margin−target` (≤ max_offset_step), иначе следующий тик снова
хочет TRV = target+большой offset.

## Дозакрыто тем же вечером (04.11)

Первая версия резала уставку только по «горячему local» и не трогала offset
по существу. Три пробела из разбора спальни закрыты:

### 1. Предиктивная отсечка по rate/TTT («долетим за N минут»)

`helpers.approach_predict_landing`: если комната **растёт** и
`predicted_minutes_to_target(e)` (geo-mean `minutes_per_degree` и `1/rate`)
≤ `APPROACH_PREDICT_MAX_MIN` — садимся тем же потолком
`room + UNDERHEAT_TRV_MARGIN`, даже когда local ещё не горячий
(датчик TRV на холодном участке / вдали от воды) или вообще недоступен.

Порог **12 мин**, не 20: ETA считается по темпу полного хода, а после среза
комната едет на остаточном тепле чугуна/воды. При ETA≈20 мин инерция не
добивает остаток → недогрев (хуже перелёта). По факту спальни: 13:49
(e=0.96, ETA≈19) — не режем, 14:31 (e=0.51, ETA≈1) — режем 26.0 → 23.29.

Гварды: `rate ≥ APPROACH_RATE_MIN` (0.01 °C/мин), `predict_max_min=0` — ветка
выключена, полоса ошибки прежняя (`e ≤ deadband + span`, т.е. ≤ 1.5),
boost/окно — как раньше не трогаем.

### 2. Evidence-гвард «комната реально растёт»

`helpers.room_is_rising(prev, prev_mono, now_mono, room)`: ΔT/Δt ≥
`APPROACH_RISE_RATE_MIN` (0.005 °C/мин = 0.3 °C/ч) при Δt ≥
`APPROACH_RISE_DT_MIN` (1 мин). Порог именно в °C/мин: спальня на подходе
растёт ~0.04 °C за 4-минутный тик (0.01 °C/мин), а квант датчика 0.01 °C на
коротком интервале выглядел бы как «рост».

`approach_trim` (offset вниз) пишется **только** при растущей комнате:
`heating_rate` — EMA и переживает часы покоя, а обучение вниз на остывающей
комнате = недогрев, который хуже перелёта. Посадка уставкой при этом остаётся
(она обратима следующим тиком), а offset — память, её портить нельзя.

### 3. Бюджет обучения на тик (инвариант 3)

`_tick_offset_snapshot` ставится в начале `_tick`; `approach_trim` и deadband
`offset_trim` считают остаток `max_offset_step − |offset − snapshot|` и молчат,
если бюджет выбран. Раньше в одном тике могли писать active_learning (+0.3) и
approach_trim (−0.3) — два писателя, двойной шаг и осцилляция. Там же:
при активной посадке upward-обучение гасится (`landing_active and
adjustment > 0` → 0): «недогрев» искусственный, мы сами срезали уставку.

## Проверка

- `python3 -m unittest tests.test_approach_predict tests.test_approach_landing -v`
  (23 + 11 тестов), весь набор: `python3 -m unittest discover -s tests` → 135 OK.
- `python3 -m py_compile custom_components/smart_thermostat/*.py`.
- Деплой: `.py` подхватывается только после **core restart** (reload entry
  оставит старый код в памяти).

Предиктив требует, чтобы **сам local рос** между тиками. Рост только
комнаты при холодном или отсутствующем local — не запас чугуна (солнце
на датчике): ни срез уставки, ни `approach_trim`.

Агрессивный decay и распад по времени пишут offset через остаток
`max_offset_step` за тик. Если `approach_trim` уже взял 0.3, decay в этом
тике молчит (раньше на 4.4 выходило около −0.6).

## Что станет видно в логах

- `last_action=approach_close` **до** пересечения цели (а не `overshoot_close` после);
- `offset_history.reason=approach_trim` на подходе, а не `offset_trim` час спустя;
- пик комнаты у цели ≤ target+0.5 вместо +1.3 (спальня 04.11: 24.3 при цели 23).

## Что стало умнее

Посадка / точность: закрываем нагрев **на подходе**, а не после перелёта, и
учим offset вниз по факту «комната растёт при срезанной уставке», а не по
инерции часами. Ось 3 (точность у цели, мягкая посадка) + ось 4 (обучение
без самоубийства): гварды ±6 / `max_offset_step` / freeze не ослаблены.
